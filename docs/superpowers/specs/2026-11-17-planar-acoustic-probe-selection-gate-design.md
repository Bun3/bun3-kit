# 평면 음향 출력 판정: 가려진 프로브가 선택 한도를 채울 때 우회 경로 허용

- 상태: 구현 (2026-11-17), JP 사용자 결정 S1 "듣는 위치 주변 프로브 일부가 문·벽에 가려져도 유효한 우회 경로가 있으면 들리게"
- 적용 패키지: `com.bun3.unity.audio.steamaudio` 0.7.0 → 0.7.1
- 관련 조사: [Steam Audio 직접음·경로 혼합](../../research/2026-09-12-steam-audio-direct-path-mixing.md) (네이티브 선택 한도 8, 이전 출력 유지)
- 첫 적용 게임: 쥬라기 낙원(JP)

## 의도

닫힌 문에 붙어 선 플레이어도 열린 길로 돌아오는 소리는 들어야 한다. 벽 너머에 실제 경로가 없을 때 무음, 닫힌 문을 통한 누출 차단은 그대로 지킨다.

## 원인

`PlanarAcousticWorld.IsRouteCovered`는 격자 연결과 두 끝점의 프로브 판정이 모두 `GridVisible`일 때만 통과시켰다. `AcousticGridQuery`는 끝점을 포함하는 프로브 중 가려진 수가 선택 한도(8) 이상이면 `SelectionUncertain`을 낸다. 네이티브 `ProbeTree::getInfluencingProbes`가 가까운 순서가 아니라 트리 순회 순서로 8개를 고른 뒤 가려진 것을 지우므로, 보이는 프로브가 선택에서 모두 빠질 수 있기 때문이다.

JP 박물관 북쪽 오른문 바로 앞(문까지 0.3u)에서 듣는 위치를 포함하는 프로브는 11개, 그중 보이는 것은 3개였다. 가려진 8개가 한도를 채워 `SelectionUncertain` → 출력 차단(-120dB). 같은 순간 네이티브는 우회 경로 3개(12.85~15.13u)를 실제로 계산했다. 0.4u 물러나면 보이는 프로브가 5개가 되어 `GridVisible`, 약 -27dB로 들렸다. 우회 경로 길이는 두 위치 모두 13~15u로 같았다.

이 판정이 보수적이었던 이유: 듣는 위치나 소리 위치의 선택된 프로브가 모두 가려지면 Steam Audio `PathSimulator::findPaths`가 계수를 갱신하지 않고 돌아가고, 호출 쪽은 이전 출력을 그대로 복사한다. 가려진 선택을 통과시키면 문이 닫히기 전 경로가 남아 새어 나올 수 있다.

## 결정

1. `IsRouteCovered`: 격자 연결 + 두 끝점에 격자상 보이는 포함 프로브가 하나 이상(`GridVisible` 또는 `SelectionUncertain`). `None`·`InvalidEndpoint`·`Disconnected`는 그대로 차단한다.
2. `TryGetPath`: 기존 조건에 **이번 네이티브 실행이 경로를 하나 이상 평가했을 것**(`TryGetPathDistanceRange` 성공)을 더한다. 거리 감쇠 콜백은 `findPaths`가 경로를 계산할 때만 불리고, 매 `Simulate` 직전에 개수를 0으로 되돌린다. 따라서 네이티브 선택이 보이는 프로브를 모두 놓쳐 이전 출력이 남은 경우는 개수가 0이라 무음이다. 이 조건은 `GridVisible`에도 적용한다(격자와 네이티브 가림 판정이 달라 같은 일이 생겨도 이전 경로를 재생하지 않는다).
3. `AcousticGridQuery`의 상태 분류는 바꾸지 않는다. `SelectionUncertain`은 여전히 정확한 격자 증거이고, 출력 정책만 네이티브 증거로 확정한다.

결과: 문 앞처럼 가려진 프로브가 한도를 채워도 네이티브가 보이는 프로브를 골라 경로를 계산하면 그 경로대로 들린다. 네이티브가 가려진 것만 고르면 이전처럼 무음이다(누출 없음). 음성(`DissonancePlanarAcousticOutput`)도 같은 `IsRouteCovered`·`TryGetPath`를 쓰므로 같이 적용된다.

## 검토한 대안

| 대안 | 판단 |
|---|---|
| 가시 프로브 비율·개수 기준 완화 | 네이티브 선택 순서를 모르므로 어떤 비율도 이전 출력 재사용을 막지 못한다. 기각 |
| 가려진 프로브를 네이티브 선택에서 제외 | Steam Audio 코어 패치·재빌드가 필요하고 공식 SDK와 갈라진다. 기각 |
| 네이티브 트리 순회 순서를 재현해 실제 선택 8개 계산 | BVH 구성에 의존해 SDK 버전마다 깨진다. 기각 |
| 프로브 반경·배치 재베이크 | 맵마다 반복되고 문 앞 같은 경계는 남는다. 기각 |
| `SelectionUncertain`을 그대로 통과(신선도 확인 없음) | 위 원인의 이전 출력 누출이 열린다. 기각 |

## 검증

- EditMode `PlanarAcousticDoorCoverageTests`(steamaudio Editor 테스트): 벽에 문(닫힘)과 우회 틈이 있는 고정 배치. 듣는 위치를 문 바로 앞에 두어 포함 11개·가시 3개(JP와 같은 조건)로 `SelectionUncertain`을 재현한다.
  - 대표: 우회 틈이 열려 있으면 `IsRouteCovered`·`TryGetPath`가 참이고 네이티브 최단 거리가 우회 길이(8u 초과)다.
  - 경계: 우회 틈도 닫으면 같은 위치에서 `IsRouteCovered`·`TryGetPath`가 거짓이다(문 뒤 프로브로 새지 않음).
- JP(로컬 `file:` 패키지): 박물관 북쪽 오른문 앞 0.5u 안쪽 측정과 문 15개 닫힘 양쪽 점 쌍 누출 검사.

## 남은 한계

- 네이티브가 가려진 프로브만 고르는 위치는 여전히 무음이다(이전 출력 재사용보다 안전한 쪽). 해결하려면 네이티브 선택 자체를 바꿔야 한다.
- 신선도 조건만 따로 겨냥한 테스트(격자는 보이고 네이티브는 가린 배치)는 두지 않았다.
