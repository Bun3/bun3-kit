# 아웃게임 트랜잭션·알림 계약 수정

> 후속 개정: 가변 편집 후 State 참조 동일성과 보관 버퍼 생성 시점은 [상태 롤백 계약](2026-09-29-outgame-state-rollback-design.md)을 따른다. 아래 내용은 이 후속 변경 이전의 기록이다.

- 근거: `f093e31` 리뷰에서 재현한 4건과 사용자의 수정 요청(“너 말대로 수정해보자”).
- 범위: Core / Items / Achievements 및 서버 회귀 테스트.
- 기존 설계: `2026-08-20-server-outgame-transactions-design.md`. 이 문서는 아래 계약을 개정한다.

## 목표

게임마다 예외·재진입 방어를 반복하지 않아도 프레임워크의 롤백과 알림이 정확해야 한다.
Items와 Achievements의 독립 패키지 경계, 세션 액터, 즉시 적용 + 스냅샷 롤백은 유지한다.
원자성은 인메모리 상태에 한정하고 DB·외부 효과의 원자성이나 자동 재시도는 추가하지 않는다.

## 재현된 문제

1. 첫 참가자의 커밋 훅 예외가 뒤 참가자를 `_txEnlisted` 상태에 남긴다. 이후 미커밋 소모도 복원되지 않는다.
2. 참조 필드를 가진 struct TState에서 `State` 대입 후 `BeginStateChange()`를 쓰면 최초 스냅샷이 현재 값으로 덮인다.
3. 트랜잭션 밖 전송의 알림 버퍼가 남아, 다음 Flags-only 트랜잭션에서 획득 델타가 다시 전달된다.
4. `onApplied`의 동기 재진입 지급이 전달 중인 span을 바꾸고 원래 ActionLog 행을 유실한다.

## 선택한 접근

콜백별 try/catch만 추가하면 첫 문제의 일부는 막지만, 참가자 내부 정리와 알림이 섞이는 구조와
공유 버퍼 재진입 문제는 남는다. 범용 이벤트 버스나 영속 큐는 이번 요구보다 크다.
따라서 **참가자 완료를 두 단계로 분리하고 모듈이 전달 중인 알림 배치를 소유**한다.
이는 변경 적용을 미루는 2PC가 아니다. 변경은 지금처럼 연산 시점에 적용된다.

## 1. 참가자 완료 계약

`ITransactionParticipant`는 다음 세 메서드를 갖는다.

```csharp
void OnCommit();     // internal finalization only; no external callbacks
void OnCommitted();  // deliver the notifications frozen by OnCommit
void OnRollback();   // restore internal state; discard notifications
```

- Core는 먼저 등록 순서대로 모든 `OnCommit`을 호출하고, 그 후 같은 순서로 `OnCommitted`를 호출한다.
- `OnCommit`은 참가 상태·스냅샷을 정리하고 알림 배치를 고정한다. 외부 게임 코드나 로그 싱크를 호출하지 않는다.
- 따라서 첫 외부 알림 시점에는 모든 참가자의 내부 완료 처리가 끝나 있다.
- 한 참가자나 알림의 예외 때문에 뒤 참가자의 완료/알림을 생략하지 않는다. 롤백도 역순으로 전원을 시도한다.
- 단일 실패는 원래 예외/스택을 보존해 보고하고, 복수 실패는 `AggregateException`으로 마지막에 보고한다.
- 커밋 알림 실패는 이미 커밋된 상태를 되돌리지 않는다. `Dispose`가 다시 롤백하지 않으며 다음 트랜잭션은 정상 동작한다.
- 모듈 내부 완료 코드는 임의 게임 콜백을 실행하지 않아야 한다. 사용자 참가자 자체의 복원 실패까지 성공으로 보장하지 않는다.
- 기존 중첩/완료 처리 중 `Begin()` 금지는 유지한다. `IsActive`는 완료 처리 중 false이고 일반 변경의 재진입은 허용한다.
- `TransactionScope` 이름은 유지한다.

## 2. 알림 배치 소유권

- 트랜잭션 커밋, 일반 연산, 전송이 모두 알림 완료 시 버퍼를 비우는 같은 규칙을 사용한다.
- 전달할 배치는 외부 코드 호출 전에 활성 기록 버퍼와 분리한다. 소비자가 받은 span은 콜백이 반환할 때까지 불변이다.
- 동기 재진입은 별도 배치에 기록한다. 재사용 버퍼/풀 등으로 워밍업 후 정상 경로 할당을 만들지 않는다.
- 앞 참가자의 콜백이 아직 알림 전인 참가자를 변경해도 그 참가자의 고정된 커밋 배치를 손상시키지 않는다.
- 모듈은 고정된 원래 변경의 ActionLog 기록을 반응 훅보다 먼저 처리한다. 따라서 원인 행이 파생 보상 행보다 앞선다.
- 로그 싱크, dirty, applied/completed 등 독립 알림 하나가 실패해도 남은 알림은 시도한다.
- 버퍼는 성공/예외 양쪽에서 정리한다. 실패한 알림을 다음 트랜잭션에서 암묵적으로 재전송하지 않는다.
- 일반 연산도 자기 내부 후처리를 마친 뒤 외부 알림을 실행한다. 특히 리젠 지급의 기준 시각은
  알림 전에 갱신해, 훅 실패나 재진입 정산이 같은 충전 시간을 다시 지급하지 않도록 한다.
- 동일 참가자 내부 알림의 재진입 보존은 필수다. 별도의 전역 비동기 이벤트 큐나 외부 저장소 재시도는 추가하지 않는다.

## 3. TState 스냅샷

- 롤백의 기준은 최초 변경 전 값이다. `State` 대입과 `BeginStateChange()`를 섞어도 이 기준은 변하지 않는다.
- struct 내부 참조 필드도 지원한다. 깊은 복사가 필요할 때 현재 값으로 원래 값의 scalar/reference 정보를 덮지 않는다.
- 기존 class의 참조 정체성, overridden Equals, 스코프 반복을 유지하고,
  struct의 State 교체 후 내부 리스트 참조를 공유하는 사례도 함께 검증한다.
- 깊은 복사는 게임이 주입하는 `snapshotState`의 책임이고, 이를 지정하지 않은 트랜잭션 내 가변 변경 가드는 유지한다.

## 4. 제약과 호환성

- 패키지 코드는 netstandard2.1 + C# 9 블록 네임스페이스. 테스트는 net10.0 + NUnit 4.
- 모든 public 멤버는 영어 XML 문서. 코드·주석·README·메타데이터는 영어. 한국어 설명은 docs/에만.
- 새 외부 의존성은 추가하지 않는다. 정상 핫패스에 클로저·LINQ·문자열 할당을 추가하지 않는다.
- 공개 참가자 인터페이스 변경에 맞춰 Core 0.7.0, Items 0.3.0, Achievements 0.4.0으로 올린다.
- 사용자 참가자는 `OnCommit`의 외부 알림을 `OnCommitted`로 이동해야 한다. XML 문서에 두 단계와 실패 의미를 명시한다.
- 퍼블리시·push·main 통합은 범위 밖이다. 변경은 현재 작업 트리에 남긴다.

## 5. 완료 증거

- 네 원래 재현을 NUnit 회귀 테스트로 추가하고 수정 전 실패를 확인한다.
- 모든 참가자 완료 후 첫 외부 알림, 단일/복수 콜백 오류, 롤백 예외의 후속 참가자 처리, 다음 거래 재사용을 검증한다.
- 두 모듈을 실제로 조합해 원장·dirty·완료 알림의 예외 및 재진입을 검증한다.
- 전달 중 span 보존, 원인/보상 원장 행 각 1회, 전송 후 Flags-only 커밋에서 델타 재발화 0회를 검증한다.
- 기존 class/값 타입 상태 테스트, 비트랜잭션 및 워밍업 후 알림 핫패스 무할당 검증을 유지한다.
- 서버 전체 Debug/Release 테스트와 Release 솔루션 빌드(경고 0)를 통과시킨다.
