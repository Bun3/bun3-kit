# Pooled Collections Design

**Date:** 2026-07-29
**Target:** `common/src/com.bun3.common` (netstandard2.1, C# 9, Unity package with `noEngineReferences: true`)
**Origin:** Improved port of `idlez-server/Server/Commons/Utility/ObjectPool`.

## Goal

Allocation-free, `using`-friendly pooled collections usable from both Unity (main thread)
and server (multithreaded) code. The defining feature over Unity's `CollectionPool` is that a
pooled collection can be **returned from a function** — ownership transfers to the caller, who
disposes it — which Unity's struct-based `PooledObject<T>` handle cannot express.

## Decisions (from design discussion)

1. **Inheritance wrappers per collection type.** `PooledList<T> : List<T>, IDisposable` etc.
   The wrapper *is* the collection: zero extra allocation, full BCL API, `using` support,
   returnable across function boundaries. Boilerplate (~20 lines × 7 types) is the accepted cost.
2. **Single concurrent pool implementation.** One `ConcurrentObjectPool<T>` backed by
   `ConcurrentBag<T>` (internally thread-local queues + work stealing → near lock-free for the
   common same-thread Get/Release pattern). No non-concurrent pool variant.
3. **Static factory API.** `using var list = PooledList<int>.Get();` — pool plumbing hidden.
   Instance pools remain possible (`new ConcurrentObjectPool<PooledList<int>>(64)`).
4. **All 7 collection types**: List, Dictionary, HashSet, Queue, Stack, SortedDictionary,
   PriorityQueue.
5. **Standalone public `PriorityQueue<TElement, TPriority>`** in `Bun3.Common.Collections`
   (netstandard2.1 has none; the server will use this class directly too).
   `PooledPriorityQueue` inherits it, same as the other wrappers.

## Components

### `IObjectPool<T>` / `IPooledObject<T>`

```csharp
public interface IObjectPool<T>
{
    int MaxRetainedCount { get; }   // read by wrappers in Dispose, before Clear
    T Get();
    void Release(T item);
}

public interface IPooledObject<T> : IDisposable
{
    void SetPool(IObjectPool<T> pool);
}
```

Method names follow the Unity convention (Get/Release), consistent with the static factory
`Get()`. Consumers never call `SetPool`; the pool re-arms items on every `Get`.

### `ConcurrentObjectPool<T>`

`where T : IPooledObject<T>, new()`. Changes from the idlez original:

- **`Interlocked` counter** instead of `ConcurrentBag.Count` (which locks and walks all
  thread-local queues). `Release` pre-increments; if over `MaxCapacity`, rolls back and drops
  the item (GC takes it).
- **No lazy static singleton.** Each pooled type holds a `private static readonly` shared pool —
  thread-safe initialization per closed generic type, no `??=` race.
- **Retention threshold:** items whose `Count` at dispose time exceeds `MaxRetainedCount`
  (default 8192, constructor-configurable) are dropped instead of pooled. Protects against one
  huge use permanently pinning a large backing array. `Count` is a proxy because
  netstandard2.1 exposes no `Capacity` on Dictionary/HashSet. The check lives in the wrapper's
  `Dispose` (before `Clear`) — the pool's `Release` cannot see `Count` through the generic
  constraint, and after `Clear` the count is always 0.
- Default capacity: `Math.Max(32, 2 * Environment.ProcessorCount)`.
- Removed (YAGNI, no current callers): non-concurrent `ObjectPool`, `PooledObject<T>` base
  class, `Initializer` callback.

### Ownership & double-dispose guard

```csharp
public void Dispose()
{
    var pool = Interlocked.Exchange(ref _pool, null);
    if (pool == null) return;   // double dispose, or directly-constructed instance → no-op
    if (Count > pool.MaxRetainedCount) return;   // grown too large → drop, GC takes it
    Clear();
    pool.Release(this);
}
```

- Double `Dispose` is a harmless no-op — the same instance can never enter the pool twice,
  eliminating the aliasing failure mode (two threads popping the same instance).
- `_pool` is re-armed by the pool's `Get()` on every rental; while an item sits in the pool its
  `_pool` is null.
- `new PooledList<int>()` constructed directly and disposed → no-op (behaves like a plain List).
- Because return-value ownership transfer is implicit, this guard is mandatory, not optional.

### `PriorityQueue<TElement, TPriority>` (Bun3.Common.Collections)

Array-backed binary min-heap mirroring the .NET 6+ API subset so later migration is mechanical:

- Constructors: `()`, `(int initialCapacity)`, `(IComparer<TPriority>)`,
  `(int initialCapacity, IComparer<TPriority>)`
- `Count`, `Comparer`
- `Enqueue`, `Dequeue`, `TryDequeue`, `Peek`, `TryPeek`, `Clear`

Note: on net8+ consumers, the name collides with `System.Collections.Generic.PriorityQueue`
only when both namespaces are imported in one file — accepted trade-off since the server
intends to use this class.

## Usage

```csharp
using var list = PooledList<int>.Get();
using var dict = PooledDictionary<int, string>.Get();

PooledList<Node> FindPath(...)
{
    var result = PooledList<Node>.Get();
    // ...
    return result;   // ownership moves to caller, who disposes via using
}
```

## Testing

New NUnit (net8.0) project `common/tests/Bun3.Common.Tests`, added to `Bun3.sln`:

- Get → Dispose → Get returns the same instance (reuse works, contents cleared)
- Double Dispose is a no-op (instance not pooled twice)
- Directly-constructed instance Dispose is a no-op
- Release beyond `MaxCapacity` drops items
- Release with `Count > MaxRetainedCount` drops the item
- Multithreaded Get/Release stress: no instance handed to two threads at once
- `PriorityQueue`: ordering, duplicate priorities, custom comparer, Clear, empty-queue
  Dequeue/Peek throws + Try variants return false

## Out of scope

- Source generator for wrapper boilerplate (revisit if wrapper count grows)
- `PooledObject<T>` base class for custom pooled types (add when a caller appears)
- Trim/`EnsureCapacity` tuning beyond the retention threshold
