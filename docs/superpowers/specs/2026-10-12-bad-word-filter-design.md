# Bad Word Filter Design

**Date:** 2026-10-12
**Target:** new package `common/src/com.bun3.badwords` 0.1.0 (netstandard2.1, C# 9, Unity package with `noEngineReferences: true`, no dependencies)
**Research:** [`docs/research/2026-10-10-bad-word-filter-research.md`](../../research/2026-10-10-bad-word-filter-research.md)
**First consumer:** jurassic-paradise nickname validation (Unity, Windows/Steam, Korean + English). A text chat consumer is expected later.

## Goal

Detect Korean and English bad words in short user text (nicknames, chat lines) with **zero managed allocation per call**, thread safety, and resistance to common evasion (inserted digits/spaces, split jamo, 2-beolsik keyboard typing, leetspeak, stretched letters). Ship a curated default dictionary inside the package so every consumer (Unity including IL2CPP, .NET server) gets it without loading code.

## Non-goals (v1)

- Masking/censoring output (`Mask`). Added together with the first chat consumer; the matcher already reports spans internally.
- Remote dictionary updates, runtime severity selection, languages other than Korean/English, contextual/ML detection.
- Steam `ISteamUtils::FilterText`. It filters per *viewer* settings, so it cannot decide rejection; a consumer may layer it on display later.
- Evasion forms deliberately not handled (see [Known limits](#known-limits)).

## Decisions (from design discussion)

1. **Own Aho-Corasick matcher instead of a library.** No candidate meets all requirements (span input, zero allocation, thread safety, match positions):
   - ToolGood.Words: only `ContainsAny(string)` is allocation-free and it returns no positions; positions need `FindAll` (allocates a list); input must be a `string`; building allocates ~96 MB transiently (`int[0xFFFFFF]` + two `bool[0xFFFFFF]`, `BaseSearchEx2.cs:324-326`); 0.9 MB DLL with unused Chinese resources.
   - NReco.Text.AhoCorasickDoubleArrayTrie: results arrive through `Func<Hit,bool>`, forcing either a per-call closure allocation or shared mutable state; unmaintained since 2022.
   - mganss/AhoCorasick: allocates per match. .NET `SearchValues<string>`: .NET 9+ only.
   - At these input sizes every implementation is sub-microsecond; the matcher is ~150 lines of textbook code. Correctness is covered by a differential test against naive search. The package stays dependency-free for both NuGet and UPM distribution.
2. **Accuracy lives in normalization + dictionary + allow list**, not the matcher. Three normalized streams feed two automata (Korean, English).
3. **Default dictionary compiled into the assembly** as a generated C# partial (non-ASCII escaped as `\uXXXX`). Source of truth is `Data~/ko.txt` and `Data~/en.txt` (`~` folders are not imported by Unity). No Addressables/Resources/file IO in any consumer.
4. **Data licenses: MIT only** (korcen, doublems/korean-bad-words, dsojevic/profanity-list) plus a Unicode confusables subset (Unicode License V3) and the obscenity leet table (MIT). LDNOOBW is excluded (CC-BY attribution adds an obligation without adding needed coverage). NC, ND, GPL and unlicensed lists are excluded.
5. **Default dictionary holds strong expressions only** (general profanity, sexual, parent insults, racial/belittling slurs). Mild words (`damn`, emphasis prefixes such as `존맛`, `개-`) pass. Grades are comment sections in the data files, not a runtime option.
6. **bun3-kit is a public repository**, so the dictionary is public. Acceptable: every source list is already public.

## Public API

```csharp
namespace Bun3.BadWords
{
    /// Immutable after construction; safe to share across threads.
    public sealed partial class BadWordFilter
    {
        /// Built from DefaultEntries on first access (type initializer). Touch it at boot to prewarm.
        public static BadWordFilter Default { get; }

        /// The shipped entries, for composing consumer-specific filters.
        public static IReadOnlyList<string> DefaultEntries { get; }

        /// Throws ArgumentException for a malformed entry (see Entry grammar).
        public BadWordFilter(IEnumerable<string> entries);

        /// No managed allocation for any input length (after ArrayPool warm-up above 256 chars).
        public bool ContainsBadWord(ReadOnlySpan<char> text);
    }
}
```

Consumer extension: `new BadWordFilter(BadWordFilter.DefaultEntries.Concat(extra))`. Tests inject small fake dictionaries through the same constructor.

## Entry grammar

Constructor entries (data files additionally allow blank lines and `#` comment lines, stripped by the generator):

```
entry    = ["!"] ["|"] word ["|"]
```

- `!` — allow entry. Suppresses block matches it fully covers (see Matching).
- leading/trailing `|` — word boundary required before/after the match. Latin entries only.
- Language is inferred: an entry containing a Hangul syllable or compatibility jamo is Korean; otherwise it is English.
- Entries are normalized with the same stream normalizer as text (Korean: stream A rules; English: stream C rules), so spelling variants of an entry collapse to one pattern.
- `ArgumentException` when: the entry is null; it has no Hangul or Latin letter (includes `!`/`|` alone and digit-only entries); a Korean entry contains anything other than Hangul and spaces (stream A would silently drop it, e.g. `18놈` → `놈`); `|` is used on a Korean entry. Duplicates after normalization are merged (`Allow`/`Short` OR, boundaries AND).

## Normalization

```
text (ReadOnlySpan<char>)
 └─ 0. common per-char cleanup
 ├─ A. Hangul stream      → KO automaton
 ├─ B. 2-beolsik stream   → KO automaton
 └─ C. Latin stream       → EN automaton (scan 1) and ENc automaton (scan 2)
```

Every stream output is never longer than the input, so one scratch buffer of input length is reused per stream.

### Step 0 — common cleanup (per UTF-16 code unit)

| Input | Result |
|---|---|
| `UnicodeCategory.Format` (zero-width, soft hyphen, bidi marks), `NonSpacingMark`, `EnclosingMark`, Hangul fillers U+115F, U+1160, U+3164, U+FFA0 | removed (no trace, no boundary) |
| Fullwidth ASCII U+FF01–FF5E | U+0021–007E (case preserved) |
| Latin-1 letters U+00C0–00FF | base ASCII letter (`é`→`e`); letters without a base (`æ`, `ß`, `ð`, `þ`) are "other" |
| Cyrillic/Greek Latin look-alikes (UTS #39 confusables subset, e.g. `а`→`a`, `с`→`c`, `о`→`o`) | Latin letter |
| Surrogates | "other" |

Case is preserved here; stream B needs it.

### Stream A — Hangul

- Keep Hangul syllables U+AC00–D7A3 and compatibility jamo U+3131–3163. Drop everything else (digits, spaces, symbols, Latin, archaic jamo). This catches `시1발`, `시.발`, `시 발`.
- Compose runs of compatibility jamo with 2-beolsik IME rules (`HangulComposer`): initial → +vowel (with compound vowels ㅘㅙㅚㅝㅞㅟㅢ) → +final (with compound finals ㄳㄵㄶㄺㄻㄼㄽㄾㄿㅀㅄ); a final followed by a vowel moves to the next syllable (a compound final splits); ㄸㅃㅉ never become finals. Syllable arithmetic per Unicode §3.12: `S = 0xAC00 + (L×21 + V)×28 + T`.
- A precomposed syllable in the input is never decomposed or extended; it flushes the composer. `시ㅂㅏㄹ` → `시발`.
- Consonants with no following vowel stay as compatibility jamo: `ㅅㅂ` stays `ㅅㅂ`.
- No initial-consonant projection of syllables (`수박` must not become `ㅅㅂ`).

### Stream B — 2-beolsik keyboard typing

- Skipped when the text has no ASCII letter.
- Keep ASCII letters (after step 0); drop everything else.
- Map with the KS X 5002 layout — consonants `q w e r t a s d f g z x c v` = ㅂㅈㄷㄱㅅㅁㄴㅇㄹㅎㅋㅌㅊㅍ, vowels `y u i o p h j k l b n m` = ㅛㅕㅑㅐㅔㅗㅓㅏㅣㅠㅜㅡ, Shift `Q W E R T O P` = ㅃㅉㄸㄲㅆㅒㅖ, other uppercase = lowercase — then compose with `HangulComposer`. `tlqkf` → `시발`, `qudtls` → `병신`.
- Stream B is scanned only when it has two or more jamo/syllables (a single typed letter is not readable as Korean, so single-character patterns never match here). A **short** Korean pattern (normalized length < 2, or containing any loose jamo) matches only when the match spans the whole stream **and** the input contains no Hangul (the Hangul stream is empty): `tq` → `ㅅㅂ` and `qt` → `ㅂㅅ` block, `tq` inside an English word or `가qt` does not. Long patterns are unaffected (`가tlqkf` still blocks via `시발`).

### Stream C — Latin

- ASCII letters → lowercase. Leet: `4 @`→a, `3`→e, `1`→i, `0`→o, `5 $`→s, `7`→t. Everything else (space, other digits and symbols, Hangul, "other") is a **boundary**; consecutive boundaries collapse to one.
- Single-letter join: three or more consecutive one-letter tokens are joined (`f u c k`, `f.u.c.k` → `fuck`).
- Scan 1: the stream as-is against EN.
- Scan 2: the stream with every run of identical letters collapsed to one (`fuuuck` → `fuck`, `shiiit` → `shit`) against **ENc**, an automaton holding block patterns that contain no doubled letter plus every allow pattern in collapsed form. `butt` (doubled) is therefore not in ENc, so `but` is not blocked; `accumulate` collapsed (`acumulate`) still suppresses `cum`.
- Boundary flags are checked against stream C positions (start/end of stream count as boundaries).

## Matching

- Each automaton holds block and allow patterns together, flagged per pattern (`Allow`, `BoundaryStart`, `BoundaryEnd`, `Short`).
- Per scan (A, B, C1, C2 separately): collect valid block spans and allow spans into stack buffers (capacity 32 each). A block span `[s,e)` is suppressed iff an allow span `[s',e')` from the same scan has `s' ≤ s` and `e ≤ e'`. Any unsuppressed block span → `true`.
- Validity rules (boundary, stream-B short rule) apply to block and allow matches alike.
- Overflow: more than 32 block spans in one scan → `true`; allow spans beyond 32 are ignored (may only cause a false positive).
- Korean has no reliable word boundaries; cross-word false positives from dropped spaces (`다시 발견` → `다시발견` ⊃ `시발`) are handled with allow entries.

## Automaton

- Trie with sorted per-state edges in flattened arrays (CSR: `int[] firstEdge`, `char[] edgeChar`, `int[] edgeTarget`); transitions by binary search. Failure links by BFS. Output enumeration through a dictionary-suffix link (`int[] outLink`, nearest terminal state on the failure chain) so all matches ending at a position are reported without allocation.
- Pattern table: id → normalized length + flags.
- All arrays are built once in the constructor and never mutated → thread-safe.

## Buffers and allocation

- `ContainsBadWord` holds no instance state. Scratch: `stackalloc char[256]` when `text.Length ≤ 256`, otherwise `ArrayPool<char>.Shared.Rent` returned in `finally`. Match buffers are `stackalloc` spans of an unmanaged struct.
- No strings, closures, LINQ, boxing or iterators on the call path.

## Default dictionary pipeline

- `Data~/ko.txt`, `Data~/en.txt`: one entry per line, `#` comments, grade sections as comments (`# == general ==`).
- `DefaultEntriesGenerator` (dotnet test project only) parses both files, validates every entry through the `BadWordFilter` constructor, and renders `Runtime/BadWordFilter.Default.cs` (header `// <auto-generated/>`, role comment, `static readonly string[]`, non-ASCII escaped).
- Test `GeneratedDefaultIsUpToDate` fails when the rendered text differs from the committed file; running it with `BUN3_BADWORDS_REGEN=1` rewrites the file instead.
- Any data change bumps the package version (no same-version republish).

### Curation (one-time for 0.1.0)

1. korcen: its `*_PROFANITY_PATTERNS` lists are literal strings (joined with `re.escape`). Take `general`, `sexual`, `parent`, `race`, `belittle`; keep pure-Hangul entries (spaces removed) as Korean, pure-Latin entries as English (≤ 3 letters get `|…|` boundaries), and skip entries mixing digits/symbols/scripts (count recorded in the research doc). Matching `FALSE_POSITIVE_PATTERNS_*` become `!` entries. Skip `minor`, `politics`, `japanese`, `chinese`, `special`, `english`.
2. doublems: add strong terms missing from step 1.
3. dsojevic: severity 3–4 entries; `allow_partial: false` → `|` boundaries; `exceptions` → `!` entries.
4. Romanized Korean (`sibal`, `byungsin`, …) goes to `en.txt`.
5. False-positive sweeps (corpora in a scratch directory, never committed), via an `Assert.Ignore`-guarded dotnet-only test that reports `Explain` reasons: English over `google-10000-english-usa-no-swears` (every hit is a false positive → `!` entries, or a `|` boundary when one pattern has more than 10 hits); Korean over NSMC (CC0, 200k sentences; review the top 100 reasons). Add `!다시발` explicitly.
6. Owner spot-checks the lists before merge.

## Tests

Shared NUnit sources under `Tests/Editor` run in both the Unity Test Runner and `dotnet test`, except where noted.

1. **Rule regression table** (fake dictionaries): one case per rule above — step 0 removals/mappings, stream A drop + composition (compound vowel/final, final moving, precomposed flush, loose jamo kept), stream B mapping incl. Shift and the short-pattern whole-stream rule, stream C leet/boundary/single-letter join/scan 2 + ENc, `|` flags, allow covering fully vs. partially.
2. **HangulComposer** unit cases.
3. **Differential test**: seeded random small dictionaries (Latin and Hangul syllable alphabets) and random texts; automaton match sets equal naive `O(n·m)` search.
4. **Default dictionary smoke**: must-block (`시발`, `ㅅㅂ`, `tlqkf`, `병신`, `fuck`, `b1tch`, `f u c k`, `fuuuck`) and must-pass (`시발점`, `다시 발견`, `수박`, `class`, `assassin`, `Scunthorpe`, `but`, `document`, `accumulate`, a list of ordinary nicknames). dsojevic rates `shit`, `dick`, `cock` severity 2, so they pass under the severity 3–4 rule.
5. **Zero allocation**: ≤256-char and >256-char (after warm-up) inputs. Unity: `Is.Not.AllocatingGCMemory()`; dotnet: `GC.GetAllocatedBytesForCurrentThread()` delta = 0 (`#if UNITY_5_3_OR_NEWER`).
6. **Thread safety**: `Parallel.For` over mixed inputs with `Default`; results equal the sequential run.
7. **Constructor validation**: each malformed entry form throws `ArgumentException`.
8. **Generated file up to date** (dotnet only).
9. **Build cost report**: `Default` build time and retained bytes written to test output; not asserted.
10. **Normalizer cases**: `TextNormalizer` step 0 and each stream on direct inputs.

`BadWordFilter` also has an `internal string Explain(ReadOnlySpan<char>)` (allocating, diagnostics only) returning `"<Stream>:<normalized span>"` for curation and test messages.

## Known limits

| Not handled | Reason |
|---|---|
| Initial-consonant projection of syllables | `수박` → `ㅅㅂ` false positive |
| Symbols imitating jamo (`^`→ㅅ, `77`→ㄲ) | false-positive risk; add on real cases |
| Digit puns mixed into Korean words (`18놈`, `10새끼`) | stream A drops digits; only the Hangul remainder is matched |
| Two-letter splits (`fu ck`, `fu_ck`), self-censoring (`f*ck`), `!` as `i` | conflicts with boundary rules |
| Leet digit adjacent to an end-boundary pattern (`ass1`) | digit maps to a letter, breaking the boundary |
| Mathematical alphanumerics (𝐬), conjoining jamo U+1100 block | not rendered by typical game fonts / not produced by IMEs; consumers should pass NFC text |
| Precomposed syllable extended by a following loose jamo (`싑ㅏㄹ`) | composer never edits precomposed syllables |
