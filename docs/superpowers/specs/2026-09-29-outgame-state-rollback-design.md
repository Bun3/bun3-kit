# Outgame 상태 롤백 계약과 선택적 보관

## 목적과 승인 범위

사용자는 오픈소스 조사 후 제안한 방향으로 수정하고, 보관과 복원 구조를 설명해 달라고 요청했다. 기존 즉시 적용 방식과 선택적 `Transaction` 사용을 유지하면서 공유 참조 회귀를 수정한다. 이번 작업은 기존 흐름의 한정된 보완이다. 기존 미커밋 수정은 보존하고 커밋·배포는 하지 않는다.

근거: [조사](../../research/2026-09-29-outgame-rollback-storage.md). 이전 알림/커밋 수정의 계약은 그대로 유지한다.

## 선택한 방식

컨테이너 전체 얕은 복사와 인스턴스별 변경 전 값 보관을 유지한다. 전면 깊은 복제는 모든 상태의 복사 비용과 참조 교체를 늘리고, 구조 변경 로그로의 전환은 현재 회귀 해결에 필요하지 않다.

### 상태 값의 복원

- 첫 인스턴스 변경에서 수량·플래그·만료·dirty 표시와 최초 `State`를 보관한다.
- `State` 대입만 사용하는 경로는 이전 값을 보관한다. 그 값 및 내부 가변 데이터를 이후 직접 수정하면 안 된다.
- 활성 트랜잭션에서 첫 `BeginStateChange()`가 열리면 **보관한 최초 State**를 `snapshotState`로 한 번 복사한다. 현재 상태와의 참조 동일성이나 클래스/구조체 여부로 복사를 생략하지 않는다.
- 이후 대입이나 편집을 반복해도 이미 확보한 깊은 복사본을 덮어쓰지 않는다.
- 복사 함수가 실패하면 편집 scope를 반환하지 않는다. 실제 편집은 시작하지 않으며 이후 정상 캡처/롤백이 가능해야 한다.
- 롤백은 인스턴스 객체는 유지하고 `State`에는 보관 값을 대입한다. 가변 편집이 있었으면 내용 복원을 보장하며, `TState` 객체 참조 동일성은 보장하지 않는다. 순수 대입 경로의 이전 참조 복원은 유지한다.

### 소유권과 사용 계약

`snapshotState`는 상태가 소유하는 모든 가변 하위 데이터의 독립 복사본을 반환해야 한다. 복사 함수는 원본을 수정하거나 인벤토리에 재진입하지 않는다. 불변 하위 값은 공유할 수 있다.

동일 아이템의 교체 전후 State 사이에 가변 하위 참조가 겹치는 경우는 지원한다. 다만 서로 다른 아이템이 같은 가변 데이터를 소유하는 구조와 외부 참조를 통한 직접 수정은 트랜잭션 지원 범위 밖이다. 프레임워크가 임의 객체 그래프를 검사하거나 추적한다고 주장하지 않는다. 롤백 후에는 `item.State`를 다시 읽어야 하며, 외부에서 보관한 과거 객체까지 제자리 복원하지 않는다. 편집 scope는 트랜잭션 scope보다 먼저 닫는다.

### 선택적 비용

- `transaction: null`, 연결했지만 비활성인 경우, 변경 API를 호출하지 않은 빈 트랜잭션에서는 롤백 전용 컬렉션/배열을 생성하지 않는다.
- 각 모듈이 활성 트랜잭션의 캡처 경로에 처음 들어갈 때 private 보관 객체를 생성한다. 이후 commit/rollback에서 내용과 참조를 비우고 용량을 재사용한다. 같은 값의 `SetProgress`처럼 최종 값이 변하지 않는 변경 API도 기존 캡처 경로에 들어갈 수 있으며, 이 최적화는 이번 범위에 포함하지 않는다.
- 아이템 보관 객체는 인스턴스 스냅샷 목록, 전체 인스턴스 사전, 재생 기준 사전을 포함한다.
- 업적 보관 객체는 캡처 여부 배열, 변경 ID/이전 상태, 지연 로그/완료 알림 목록을 포함한다. 현재 즉시 알림 경로와 재진입 안정성은 유지한다.
- 기본 기능의 컬렉션과 알림 전달 버퍼까지 없앤다는 의미는 아니다. Core 패키지 참조는 유지한다.
- 트랜잭션 밖에서는 `snapshotState` 없이 편집 scope와 `MarkChanged`를 사용할 수 있다. `ItemInventory.BeginTransaction()` 일괄 작업도 독립적으로 유지한다.

## 검증과 호환성

공유 리스트를 가진 클래스 대입 후 편집, 여러 번 교체/편집, 참조 필드를 가진 구조체, 순수 대입 참조 복원, 복사 실패 후 재시도, 트랜잭션 없는 사용을 검증한다. 비용 검증은 버퍼 내부 필드 이름에 결합한 reflection 테스트 대신 실제 할당량과 동작을 이용한다.

공개 생성자/메서드 시그니처는 유지한다. Items는 가변 편집 후 참조 동일성 계약 변화로 `0.4.0`, Achievements는 내부 보관 비용 개선으로 `0.4.1`로 올린다. Core는 이번 변경에서 수정하지 않으며 이전 작업의 `0.7.0`을 유지한다. netstandard2.1, C# 9, 영어 public XML 문서, 빌드 경고 0을 지킨다.

최종 설명 문서는 독립 사용 예제, 보관 시점/대상, rollback/commit 순서, 상태 복사 예제, 지원 범위를 담는다. DB 롤백·프로세스 장애 복구·동시성 격리를 제공한다고 설명하지 않는다.
